AEGISGRAPH / ENGINEERING MAP / 27 OCTOBER 2026

From evidence to investigation

AegisGraph turns documents, NVD/STIX/KEV catalogs and scanner reports into cited workspace evidence. Optional Ollama mode now runs real local extraction and semantic embeddings; the hash/rule demo remains available in a separate database. Neon and Neo4j await live connection checks. Remediation execution is not implemented. Investigation evidence can also be downloaded locally as revision-checked text and JSON reports.

Solid boxes: implemented locally. Dashed boxes: configured or planned. No external fonts, scripts or diagram services are required.

System architecture

FastAPI enforces workspace roles. SQLite or Neon stores extraction batches, topics and request audit events. Queries traverse the embedded graph; Neo4j is an optional derived copy, not the active query engine. Ollama mode is loopback-only and rejects mixed embedding model profiles; it does not require cloud credentials.

Scanner report and source flow

Trivy vulnerability JSON, OSV JSON and SARIF 2.1.0 are accepted through file upload. SARIF supports located CodeQL/Semgrep results. Selected fields become quoted observations; raw snippets and network requests are omitted. Secret-scanner SARIF is rejected. No scanner is executed by the import endpoint.

LangGraph investigation workflow

LangGraph coordinates evidence retrieval, conflict review and potential-route tracing. Retrieval can now use real local Ollama embeddings and previously model-extracted facts. The workflow itself remains deterministic and read-only, with no generated commands or durable agent session. Analyst review supports fresh TXT/JSON downloads with quote-span and workspace-revision validation; generated reports are not stored as durable agent sessions.

Document lifecycle and restart recovery

Sources and atomic operation checkpoints stay on disk. Completed batches, themes and audit metadata persist in SQLite/Neon. Restart reconstructs the graph and resumes nonterminal jobs whose source files remain available. Hosted disks/object storage still need configuration.

Repository security and runtime boundaries

GitHub workflows are configured for Semgrep rules, redacted Gitleaks history scans and CodeQL analysis. Gitleaks ran locally with no leaks; Semgrep local execution is blocked by its Windows socket error. CI results must be checked after push. Runtime controls enforce roles, upload limits, per-process rate limits and metadata-only audits.

Upstream projects and boundaries

  • LangGraph — Installed LangGraph workflow; optional real Ollama extraction and semantic embeddings supply its evidence. No model-driven remediation or durable agent sessions.
  • Trivy — Offline vulnerability JSON adapter implemented. Scanner execution and misconfiguration imports are not integrated.
  • OSV-Scanner — Offline dependency report adapter implemented. OSV scanning itself is external.
  • Semgrep — SARIF report import, local rules and pinned CI setup implemented. Local Windows RPC failure prevents a passing scan claim.
  • CodeQL — SARIF report import and GitHub workflow configured; GitHub code-scanning availability and CI results remain to be verified.
  • Gitleaks — Checksummed CLI verified locally; full committed history scan passed. Pinned redacted CI scan configured. Secret reports are not ingested.
  • ZAP — Future localhost web-security testing; not installed or run in this integration.
  • Nuclei — Future authorized asset checks; no scan execution or report adapter implemented.
  • Ollama — Loopback-only adapter for installed local qwen2.5-coder and nomic-embed-text models. Real extraction and semantic embeddings verified; no cloud fallback or model downloads.
